# SIM-ONE Alpha Support

## Start With The Documentation

Use the following project documentation before opening a request:

- [README](README.md) for installation, onboarding, configuration, and usage;
- [documentation hub](docs/README.md) for architecture, operations, and
  subsystem references;
- [DeepWiki](https://deepwiki.com/dansasser/sim-one-alpha) for generated,
  source-linked codebase exploration and repository-grounded questions that
  may not require an issue;
- [changelog](CHANGELOG.md) for release contents and user-visible changes;
- [contributing guide](CONTRIBUTING.md) for source builds and pull requests.

## Where To Ask

Use [GitHub Issues](https://github.com/dansasser/sim-one-alpha/issues) for:

- installation and onboarding problems;
- usage questions not answered by the documentation;
- reproducible software defects;
- documentation corrections;
- feature requests with a concrete user problem and desired outcome.

Search open and closed issues before filing a new one. Use one issue for one
problem so it can be reproduced, discussed, and resolved independently.

Do not use a public issue for:

- security vulnerabilities, exposed credentials, or private data: follow the
  [Security Policy](SECURITY.md);
- harassment or conduct concerns: follow the
  [Code of Conduct](CODE_OF_CONDUCT.md);
- general pull-request guidance: follow the
  [Contributing Guide](CONTRIBUTING.md).

## Information To Include

Provide enough detail for another person to reproduce or understand the
request:

- SIM-ONE Alpha version or commit;
- operating system and installation method;
- the command, connector, or interface involved;
- expected and actual behavior;
- minimal reproduction steps;
- relevant logs with secrets and private data removed.

For feature requests, describe the affected user or workflow, the problem being
solved, and the outcome the change should provide.

## Support Boundaries

SIM-ONE Alpha 0.1.x is a beta release maintained through the public repository.
Public support is provided on a best-effort basis and does not include a
guaranteed response or resolution time.

The project cannot provide support for unreviewed local modifications,
unsupported operating environments, third-party service outages, revoked or
misconfigured provider credentials, or upstream products outside SIM-ONE
Alpha's control. A report is still useful when SIM-ONE Alpha handles one of
those conditions incorrectly.
